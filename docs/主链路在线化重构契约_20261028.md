## 2. 阶段推进方式（硬约束）

- **逐帧推进**：Stage 2~6 全部在 `for k = 1:n_frames` 循环内，帧 k 只允许读取第 k 帧及以前的信息。
- **状态跨帧保持**：两站各一份跟踪器状态；融合中心一份系统航迹状态；关联策略各一份累计状态。
- **禁止**：任何跨阶段的"整段预计算"（原 `run.m` Phase 6 整段匹配、Phase 7 整段融合必须消失）。
- **单测口径**：单元测试断言"第 k 帧的输出与跑满 N 帧后取第 k 帧完全一致"（因果性）。


### 3.2 统一接口（冻结，两个队友按此实现）

```matlab
% 创建
S = online_assoc.init_strategy(method, params);
%   method ∈ {'dualgate','nn','sequential','mewf'}
%   S.method   方法名
%   S.acc      逐对累计证据（结构体数组，键 = (r1_id, r2_id)）
%   S.params   拷贝的参数（只读）

% 逐帧推进
[cands, S] = online_assoc.update_candidates(S, local1, local2, k, params);
%   local1/local2 — 本帧两站局部航迹数组，元素字段：
%       id, x(4x1), P(4x4), life, truth_idx
%   cands — 候选对结构体数组，字段：
%       r1_id, r2_id   两站航迹 ID
%       score         越大越可信（各方法统一为"越大越好"）
%       dist_km       本帧 Haversine 距离
%       d2            本帧马氏距离平方
%       vdiff         本帧速度差模 (km/s)
%       vtol          本帧速度容差 (km/s)
%       n_coexist     截至本帧的共现帧数
%   只返回"通过本方法自身门限"的候选；**不做 1v1 指派，不做 M/N 确认**
```

### 3.3 各方法语义（保证对比公平）

| 方法 | 候选生成规则 | score |
|---|---|---|
| `nn` | 本帧距离最近即成候选，**无门限** | 1/(1+dist_km) |
| `sequential` | 共现帧中马氏通过率 ≥ `dualgate_maha_ratio`（默认 0.8）且平均距离 < T1 | 马氏均值越小越高 |
| `dualgate` | 本帧：距离 < T1 且马氏 < 门限 且速度差 < kappa×容差 | 与 sequential 同口径 |
| `mewf` | 四项证据（距离/马氏/速度/连续段）在**截至本帧**的共现帧上累积，综合分 ≥ `mewf_score_thr` | 综合分 |

> **关键**：四种方法的候选生成统一走"逐帧 + 自身累计"，**M/N 序贯确认与 1v1 指派由融合中心统一执行**。
> 这样对比的是"证据本身好不好"，而不是"谁用了更狠的门限"。

### 3.4 MEWF 在线化的证据累积

原批处理用"全部共现帧"算均值；在线版改为**滚动累计**：

- `n_coexist`：共现帧计数
- `sum_ed`：Σ exp(-d²/2σ_d²)
- `n_maha`：马氏通过帧计数
- `n_vel`：速度通过帧计数
- `run_dist_ok`：当前连续距离合格段长度；`max_run_dist_ok`：历史最长

综合分 `S = (w_d·E_d + w_m·E_m + w_v·E_v + w_c·E_c)/Σw`，其中 `E_c = max_run/n_coexist`。
**累计只增不减 → 确认是单调事件**，天然适合在线。

### 4.1 目录与接口

```
fusion/+online_fuse/

    algorithms/
        scc.m  bc.m  ci.m  fci.m
```

```matlab
% 创建
F = online_fuse.init(method, params);
% 逐帧
[x, P, F] = online_fuse.fuse_step(F, est1, est2, k, params);
%   est1/est2 — struct('x',4x1,'P',4x4)
%   F.P12 — BC 用的跨帧互协方差（其它算法忽略）
%   断连（k 不连续）时 F.P12 置零
```

### 4.2 BC 的 P12 递推（冻结）

```
P12(k) = F·P12(k-1)·F' + 0.5·Q
P12(k) = α1·α2·P12(k)        αi = sqrt(tr(P_i)/tr(P_i,pred))
对角元钳制：P12(i,i) ≤ 0.8·min(P1(i,i), P2(i,i))
```

必须做**真 BC**（不能退化成 SCC）。批处理线 `update_cross_covariance` 的启发式递推已导致 BC≡SCC，
在线版要保证 P12 不被压到 0：新增 `bc_min_p12_scale`（默认 0.05）保底缩放下限。

## 10. 勘误（2026-10-28 复核追加，不改上文原文）

### 10.1 §3.1 的 `strategies/` 与 §4.1 的 `algorithms/` 实际都是包目录

上文目录树里写成普通子文件夹 `strategies/`、`algorithms/`，与实现不符。实际落盘为：

```
tracker/+online_assoc/           % 不含 strategies 子目录
    init_strategy.m  update_candidates.m  evidence.m  accumulate_evidence.m
tracker/+online_strategies/      % 策略本体另起一个同级包
    nn.m  sequential.m  dualgate.m  mewf.m
fusion/+online_fuse/
    init.m  fuse_step.m  p12_finalize.m  ...
    +algorithms/                 % 注意有加号：嵌套包
        scc.m  bc.m  ci.m  fci.m
```

调用名相应为 `online_strategies.dualgate`、`online_fuse.algorithms.scc`。

### 10.2 为什么不按原文写成 `strategies/`

普通子文件夹不在 MATLAB 搜索路径上，放在 `+online_assoc/` 里面既不能被当作包成员
（`online_assoc.dual_gate` 找不到），也不会被 `addpath` 收进来，函数实际是**不可见**的。
只有两种可用写法：

| 写法 | 调用名 | 备注 |
|---|---|---|
| `tracker/+online_assoc/+strategies/dualgate.m` | `online_assoc.strategies.dualgate` | 嵌套包，**MATLAB 支持** |
| `tracker/+online_strategies/dualgate.m` | `online_strategies.dualgate` | 本实现选的方案 |

**注意**：`收尾报告` 遗留项 6 把原因写成"MATLAB 不支持嵌套包"，这是错的——
本仓库的 `fusion/+online_fuse/+algorithms/` 本身就是嵌套包，且工作正常。
真正的原因只是"普通子文件夹不在搜索路径上"。两种写法都对，本实现选了同级包，
好处是策略包可以脱离 `+online_assoc` 单独 `addpath`、单独测试。

### 10.3 §9 验收第 4 条的口径说明

第 4 条要求"配对 36/36、长度比 ≈1.25"，那是 **1950 帧全量**下的上一版结果。
900 帧截断运行时，只有 37 条航迹中的前 20 条走完完整走廊，配对自然降到 20/20，
长度比 1.233。两者不矛盾，但**引用时必须写明帧数口径**，不能混用。

另需注意：2026-10-28 复核实测（详见 `docs/收尾报告复核_20261028.md` §3.3）：

   已新增 `simulation/detection_rng.m` 修复；修复后单站航迹 37/37 逐条与上一版相同。

   仍低于上一版的 36/36、1.250，差距集中在 1 个目标（#34 CSZ9278，79→53），
   根因是硬马氏门限在 NEES≈3.8（协方差过度自信）下的级联失效。
