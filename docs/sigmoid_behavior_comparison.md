# Bug vs Fix Sigmoid 行为对比总结

## 核心结论

| 场景 | ct_mu | Bug 版 P_CT→CV | Fix 版 P_CT→CV | 哪个对转弯有利？ |
|------|-------|---------------|---------------|----------------|
| 直线段 | 0.0 | 0.00038 (极低) | 0.00562 ≈基线 | ✅ **fix 版正确** |
| 转弯中 | 0.5 | 0.00515 (高) | 0.00085 (低) | ✅ **fix 版正确** |
| 强转弯 | 0.8 | 0.00593 (极高!) | 0.00007 (极低) | ✅ **fix 版正确** |
| 强转弯 | 1.0 | 0.00599 (最高!) | 0.00001 (最低) | ✅ **fix 版正确** |

**Bug 版在转弯段把 P(CT→CV) 拉到最高 (0.006)，相当于 CT→CV 以最大概率转移——这正是论文说的 "Config#51 无效"的原因。**

## Bug 版改善来源推测

Bug 版在转弯场景中反而"改善"了——不是因为 Sigmoid 方向正确，而是因为它产生的效果与 Config#51 配合产生了某种**有益的补偿效应**：

1. Config#51 使用 ct_dwell=660，P(CT→CV)基线 = 0.006
2. Bug 版 Sigmoid 在转弯段把 P(CT→CV) 提高到接近 0.006（基线最大值）
3. 同时 exp_decay/linear 模式会降低到 0.001-0.0005
4. **所以 bug 版的效果是：Config#51 + bug_Sigmoid ≈ Config#51 alone**（因为 CT→CV 没有被压低，反而保持高值）

等等——这不合理。如果 bug 版只是"Config#51 alone"的效果，那不应该比 Config#51 alone 更好。

让我重新考虑：bug 版实际上改变了 Ct→CT（自环概率）：
- `P_CT→CT = 1 - P_CT→CV`
- Bug 版：ct_mu=0.8 时 P_CT→CT = 1-0.00593 = 0.99407
- Fix 版：ct_mu=0.8 时 P_CT→CT = 1-0.00007 = 0.99993

两个都极高，差别在于 fix 版更极端。

**关键区别**：Bug 版的 ct_mu 低时（直线段）P_CT→CV=0.00038（极低），而 fix 版为 0.00562（接近基线）。

这意味着：**bug 版在转弯场景的全局效果中，因为 ct_mu 在转弯过程中会"短暂偏低"（mu 有滞后），所以经常触发低 P_CT→CV → CT 粘住 → 这个效果恰好弥补了 Config#51 在高 Q 下 CT 模型预测过大的问题。**

简单来说，Bug 版的行为像一个**低通滤波器**：它对 mu 的变化反应迟钝（因为 mu 低时压低 P_CT→CV）。这对于 ct_mu 有噪声波动的场景反而产生了稳定性优势。

Fix 版的行为像一个**锐利开关**：ct_mu > threshold 后迅速压低 P_CT→CV。

## 修复后预期改善

基于以上分析，修复后的 Sigmoid 在转弯场景的预期行为：

1. **ct_mu 高的帧**（确实在转弯）：P_CT→CV → 几乎 0 → CT 死死粘住 → 改善转弯跟踪
2. **ct_mu 低的帧**（直线/转弯过渡）：P_CT→CV → base_p → 正常切换，不会错过直线性
3. **过渡帧**（转弯刚结束）：ct_mu 会从 0.8 降到 0.2 以下（滞后），fix 版会恢复正常切换 → 及时释放 CT

相比 bug 版，fix 版的主要优势是：
- **不会有直线段的 "CT 粘住" 副作用**（bug 版 ct_mu=0 时 P_CT→CV=0.00038）
- **转弯段更激进**（P_CT→CV 可以压到 0.00001 vs bug 的 0.00593）

**因此预期修复后改善幅度 ≥ bug 版本**：
- Bug 版本实测平均改善 +6.1%
- 修复后预计 **+8~12%**（消除了直线段的副作用）

但如果实验结果显示修复后没有改善甚至变差，最可能的原因是：
1. Sigmoid 的调整幅度相对于观测似然度的影响太小（p=0.006 的级别，对 mu 的实际影响微乎其微）
2. Config#51 的高 Q 掩盖了差异

## Sigmoid vs exp_decay 在 fix 版下的对比

fix 版 sigmoid 要求 `exp(kp * (ct_mu^power - threshold))` 中的 exp 项要大才能压低 P_CT→CV。

对比 exp_decay 和 sigmoid_fix (kp=9, threshold=0.3, power=1.0)：

| ct_mu | exp_decay(0.006*exp(-3*ctmu)) | sigmoid_fix | ratio |
|-------|------------------------------|-------------|-------|
| 0.0 | 0.006000 | 0.005622 | 1.07x |
| 0.2 | 0.003293 | 0.004266 | 0.77x |
| 0.4 | 0.001807 | 0.001734 | 1.04x |
| 0.6 | 0.000992 | 0.000378 | 2.63x |
| 0.8 | 0.000544 | 0.000066 | 8.24x |
| 1.0 | 0.000299 | 0.000011 | 27.18x |

**exp_decay 在 ct_mu 低至 0.2 时就开始衰减，sigmoid 直到 threshold=0.3 后才开始衰减**

→ **exp_decay 在"弱转弯"段更敏感**，sigmoid 需要更强的转弯信号才响应

→ 这解释了为什么在左缓转（rate_0p7）场景中，有一个批次出现 -38% 的极端恶化——ct_mu 可能始终在 0.2~0.4 之间（弱转弯），此时 sigmoid 完全不响应（p≈base_p），而 exp_decay 已经开始压制了

**结论**：fix 版 sigmoid 的性能很大程度上取决于 threshold 是否对准了实际 ct_mu 的水平。对于强转弯（uturn, rate_1p3），sigmoid 应优于 exp_decay；对于弱转弯（rate_0p7），exp_decay 可能更鲁棒。
