**方法：** 零源码改动，通过 `params.imm_turn_rate_rad_per_sec` 注入不同候选值  
**实验：** 1 种子 × 4 场景 × 6 候选 turn_rate = 24 次 run

## 二、核心结论

### 结论 1：turn_rate mismatch 确认是主要瓶颈

**注入真实 turn_rate 后平均改善 +13.7%**（>10% 阈值），证明 CT 模型转弯率假设错误是大转弯跟踪误差的核心来源之一。

### 结论 2：离散多模型思路成立，且比"用真实值"还好

**MM上界（候选集里选最优）平均改善 +15.6%，甚至超过 Oracle 的 +13.7%。**

原因在 left_rate_1p3 场景：真实 turn_rate=1.3°/s，但最佳模型 turn_rate 是 0.7°/s（RMSE 5.782 < 真实值的 6.212）。这是因为雷达量测噪声、Q 参数、CV/CT 权重等综合作用下，**"经验最优模型"未必等于"真实物理参数"**。

**这对多模型实现是重大利好**：不需要精确估计真实 turn_rate，只要候选集覆盖了"经验最优值"附近，多模型就能发挥作用。

### 结论 3：效果高度场景依赖

| 场景类型 | Oracle 改善 | 解读 |
|---------|-----------|------|
| left_rate_1p3 (左转急) | **+28.5%** | turn_rate 极敏感，多模型收益巨大 |
| left_rate_0p7 (左转缓) | **+14.4%** | turn_rate 敏感，多模型明显收益 |
| right_rate_0p7 (右转缓) | +2.2% | Default 已接近最优，收益小 |
| right_rate_1p3 (右转急) | -0.7% | 对 turn_rate 不敏感（曲线平坦）|

**左转场景改善大、右转场景改善小**——因为默认 CT 模型是左转(turn_rate=+1°/s)，左转场景下 CT 权重高，turn_rate mismatch 影响被放大；右转靠 CT-right 兜底，鲁棒性更好。

### 结论 4：turn_rate 曲线形态支持"选最优"机制

观察 left_rate_0p7 的 RMSE vs turn_rate：
```
0.5°/s → 6.862
0.7°/s → 5.443  ← 最低（真实值）
1.0°/s → 6.355
1.3°/s → 7.085  ← 单调上升
```
曲线在真实值处有明显极小值，**说明"覆盖候选值 + 选似然最大"的多模型机制能锁定最优**。

但 right_rate_1p3 的曲线很平（5.18~5.69），说明急转弯场景下 turn_rate 影响被其他因素掩盖。

## 三、实现可行性评估

### 改动量
`ukf_imm.m` 从 3 模型扩到 5/7 模型：
- `create_imm`：创建更多 UKF 实例（已有 ukf_ct/ukf_ct_right 模式，照搬即可）
- `prepare_imm` / `update_imm`：少数硬编码的 3 模型组合（`x_comb = mu(1)*cv + mu(2)*ct + mu(3)*ctr`）改成 `for j=1:M` 循环求和
- `Pi` 矩阵：从 3×3 扩到 5×5/7×7
- mixing / 似然 / 钳位：**已用 M 参数化循环，无需改**

总体改动量：**中等**（约 50-80 行，集中在 create_imm 和两处组合公式）

### 推荐候选值
基于扫描结果，建议 **5 模型**：
```
CV(直线) + CTL(0.7°/s) + CTL(1.5°/s) + CTR(0.7°/s) + CTR(1.5°/s)
```
- 0.7 和 1.5 覆盖了 left 场景的两个改善峰（left_rate_1p3 最佳在 0.7，left_rate_0p7 最佳也在 0.7）
- 1.5 给急转弯兜底
- 对称的左/右各两个，加 CV 共 5 个

或更保守的 **7 模型**（覆盖更密）：CV + {0.5, 1.0, 1.5}°/s × {左,右}

### 预期实际收益
- MM上界（完美选择器）：+15.6%
- 实际多模型（似然度在线选择）：预计 **+8~12%**（考虑选择器不完美）
- 远好于已证伪的 Sigmoid（-1.7%~-7.7%）

## 四、下一步建议

### 已验证
- ✅ turn_rate mismatch 是真瓶颈（Oracle +13.7%）
- ✅ 多模型上界可观（+15.6%）
- ✅ 候选集不需精确匹配真实值

### 建议路径
1. **先做多种子验证**（3-5 种子），确认 +15.6% 上界不是单种子偶然
2. **若多种子仍 >10%**，进入源码修改：把 ukf_imm 扩到 5 模型
3. **实测在线选择器收益**：用似然度做模型选择，看能否逼近上界

### 风险提示
- right_rate_1p3 等急转弯场景 turn_rate 不敏感，多模型在此收益有限
- 实际收益依赖似然度选择器质量，可能明显低于上界
- 单种子结果需多种子复核
