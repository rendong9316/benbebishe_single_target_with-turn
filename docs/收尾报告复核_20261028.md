### 3.3 1950 帧全量：先修随机流，才看得清 1.250→1.211 到底是谁的账

## 4. 六处与事实不符

### 4.1 §3.2 的"近共视 vs 覆盖互补"解释是错的（最影响论文）

报告原文：

> 默认模型集（**近共视**）下融合增益偏负/微弱，与 3.1 **覆盖互补**场景 +28.1% 不矛盾——
> 它正好印证"融合增益取决于几何/模型匹配"的论文论点：**近共视时单站已较好，覆盖互补时融合收益显著**。

事实：
- §3.2 那张表来自 `experiments/run_online_assoc_compare.m`，该脚本第 41 行硬编码
  `p = params_coverage_online()`——**它跑的就是覆盖互补布设，不是近共视**；
- 两次运行的**唯一差别是 IMM 模型集**（0.7/1.5 vs 0.05/0.2），同一场景、同一门限、同一 `M/N`；
- 增益从 −4.6% 跳到 +28.1%，**33 个百分点全部来自模型集**，与几何无关。

这与项目自己的上位文档结论一致（`跨区双站在线配对融合验证报告_20261028.md` §4.3：
"融合增益不由融合算法决定，而由前端模型匹配度决定"）。**收尾报告把这条已验证的机理
错记成了"几何差异"，等于把最关键的敏感性藏了起来**。若照此写进第 5 章，答辩时
被问"你这个 +28.1% 是不是调参调出来的"将无法回答。

**正确写法**：把"模型集敏感性"作为一个显式小节给出（0.7/1.5 → −4.6%，0.05/0.2 → +28.1%），
并说明 0.05/0.2 的来由（本场景实测转弯率中位 0.012 °/s）。

### 4.3 §2.5 "BC 做真 BC / 证真 BC 递推生效"——证据不足

- 实跑 BC=7.506 vs SCC=7.503，差 **0.003 km（0.04%）**；
- 单元测试 T2 显示 BC 与 SCC 的**状态差 1.4e-14**，只有协方差不同；
- 这点差别不是递推出来的，是 `fusion/+online_fuse/p12_finalize.m:59-75` 里
  `bc_min_p12_scale`（默认 0.05）**人为设的相关度下限**造出来的：
  当 `||C||_F < 0.05*sqrt(4)` 时把奇异值整体放大到该下限。

所以准确说法是："BC 按契约实现了递推，且在相关度被钳到 5% 时与 SCC 的差异为 0.04%，
与实测 ρ=0.085 自洽"——**不能**说"证真 BC 递推生效"。反过来，若真按 BC 的定义
（`P12 = F·P12·F' + 0.5·Q`，两站滤波器各用各的 Q），本仿真里两站量测噪声独立、
真值轨迹共享，ρ 本来就该接近 0，**BC≈SCC 是正确结果**，不是缺陷。
用 0.05 的下限去"制造差异"，是把结论写成了参数。

## 5. 三个"结论层"问题（比事实错误更伤）

### 5.1 "查全率 100%"是公式自带的，不是结果

`evaluation/evaluate_paper_metrics_online.m:67`：

```matlab
m3.recall = n_correct / max(sum(covered) + n_wrong, 1);
```

`covered` 就是"被正确配对覆盖的目标"，分母等于分子（无误配时），**恒等于 100%**。
900 帧实跑的真值是：**20/20 正确，但 37 个目标里有 17 个完全没配上（n_missed=17）**，
真实查全率 = 20/37 = 54%。报告把"20/20 全部正确"当成完备性证据，与这个公式互相印证了错误。

修法：`recall = n_correct / max(r.scenario.n_targets, 1)`（或按"应配对目标数"）。
这是六项考核指标里"正确匹配概率"的口径，论文第 6 章会直接引用，必须改。

### 5.2 "MEWF 累计只增不减 → 确认单调"不成立

契约 §3.4 与报告 §2.2 都写"累计只增不减 → 确认是单调事件"。但实现是：

```matlab
% tracker/+online_strategies/mewf.m:38-42
E_d = a.sum_ed / a.n_coexist;      % 均值，可降
E_m = a.n_maha / a.n_coexist;      % 比值，可降
E_v = a.n_vel  / a.n_coexist;      % 比值，可降
E_c = a.max_run_ok / a.n_coexist;  % 分子封顶、分母涨，必然趋 0
score = (E_d + E_m + E_v + E_c) / 4;
```

四项全是**比值**，分母 `n_coexist` 一直涨，分数就会降。
单元测试 T5 自己打印的序列就是 **0.999 → 0.999 → 0.998 → 0.934 → 0.895 → 0.868**（单调下降），
但断言却改成只检查"累计量非零"（`n_coexist==6 && sum_ed>0`），等于把要证的命题换掉了。

后果：`mewf_score_thr=0.55` 下，一条距离稍远但持续共现的航迹，分数会随时间**跌破门限**、
候选消失；这不是"确认单调"，而是"确认只在某个时间窗内可能"。第 4 章若以"单调确认"作为
MEWF 相对整段版的优势，这个论证站不住，需要改写成"证据累积 + M/N 确认"，或把 E_c 改成
`max_run_ok / min(n_coexist, K)` 之类不随分母衰减的形式。

### 5.3 一致性诊断（指标 7）报了但没读

900 帧实跑：

```
NEES: R1=4.07  R2=1.12     [一致时应 ~2]
rho(R1,R2)=+0.085
theoretical: indep=8.728  optimal(rho)=9.056  actual=7.503
```

- **NEES 4.07 / 1.12**：R1 的滤波器明显过度自信（协方差偏小约 2 倍），R2 偏保守。
  这直接影响 BC/CI 的权重，也是"单站误差 15.9 km"的一部分来源，报告一字未提。
- **actual(7.50) < optimal(9.06)**：同一个模块打印的"理论界"比"实际"还差。
  这不是造假——`consistency_analysis` 的 `opt_rms` 只在**标量权重** `w·e1+(1-w)·e2`
  上求最优，而 SCC 用的是**矩阵权重**，两者不是同一个界；但这意味着"理论界"这一行
  目前**不可用于论文**，否则审稿人一眼看出"实测优于理论下界"。要么改成矩阵权重的最优界，
  要么删掉这一行只留 ρ 与 NEES。
