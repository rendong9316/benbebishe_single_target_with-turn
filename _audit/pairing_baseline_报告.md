# 跨站航迹-航迹配对（TTTA）基线对比报告

> 用途：论文第 4 章 4.4 节"关联算法对比"的实验数据与解读。
> 数据文件：`pairing_baseline_results.csv`（32 行 = 8 组 × 4 方法）
> 生成脚本：`run_pairing_baseline.m` → `load_aligned_snapshots.m` + `compare_pairing_methods.m`

## 1. 实验设置

| 项 | 配置 |
|---|---|
| 场景 | `adsb_0002`（42 架，单点稀疏）× 5 seed；`adsb_span`（15 架，跨域长航迹）× 3 seed |
| 种子 | adsb_0002: 101–105；adsb_span: 201–203 |
| 模型集 | 优化集 CT 0.05/0.2 °/s（与论文主线一致） |
| 硬约束 | Pd=0.6, Pfa=1e-3, dt=30 s, R2 起始偏移 13 s |
| 配对层级 | **跨站航迹-航迹（TTTA）**，与点-航迹 Oracle 关联无关 |
| 评估基准 | 双站 truth_idx 相等且 >0 判为正确配对；`n_true_both` 为双站共现真实目标数 |

四种方法：
- **NN**：纯位置距离（共存帧平均 Haversine）贪心 1v1，无门限
- **Sequential**：位置粗筛 T1 + 马氏门限（D²<5.99 占比≥0.8）后贪心 1v1
- **三判据（dualgate 默认）**：位置 + 马氏 + 速度一致性
- **双门限（消融）**：关马氏 + 关速度，仅位置 + 方差门限

## 5. 结论与解读（诚实版）

1. **稀疏场景下三判据在"配对正确率"上无优势。** 因为 Oracle 点-航迹关联 + 纯预测续存保证了单站航迹不断裂、质量高，稀疏目标间距大，NN 的最近邻恰好总是正确。这与开题"NN 适用于目标稀疏场景"的判断一致——**不是算法失效，是场景没有误配机会**。

2. **三判据的价值在"拒绝低质量配对以提升融合精度"。** 三判据比 NN 少配约 2 对（漏配 2.13 vs 0），这些被拒绝的是共存距离大（>35 km）的配对；拒绝后进入融合的配对质量更高，SCC RMSE 降 2.21%。机理：融合精度取决于最差的输入配对，门限起到"剔除污染源"的作用。

3. **速度判据在本数据集未带来额外增益。** 消融"双门限"（关马氏+速度）RMSE 反而最低（8.093），说明当前场景下"位置+方差门限"已足够筛选，速度判据的收益被更严格的漏配抵消。**这不否定速度判据，而是说明本数据集缺乏"机动交叉"这类速度判据才能分辨的场景。**

4. **方法论 caveat（论文必须交代）：** 各方法融合 RMSE 是在各自配对集合上计算的，配对数不同（NN 42 vs 双门限 29），存在样本选择偏差。严格公平的比较应在**同一正确配对集合**上对比融合精度，或报告"单配对融合精度"而非总量 RMSE。

## 6. 局限与后续

- **缺密集交叉场景**：`multi_cross` 是唯一能体现三判据防误配价值的场景（目标交叉、机动、NN 会错配）。**建议补跑 multi_cross**，这是把"三判据比 NN 好多少"讲清楚的关键。
- 建议补一个"固定配对集合"的对照实验，消除样本选择偏差。
- 覆盖率：三判据 34.3% vs NN 34.4%，差异 <0.1 个百分点，可忽略。
